# Installation and first access

Moxnox Omni is started from a terminal and operated from a browser. The terminal
is needed to install, start, stop and restart the process. Reading messages,
classifying leads, reviewing replies and editing automations happens in the
cockpit.

## Local first run

Requirements: Git, Node.js 24+ and a recent browser.

```bash
git clone https://github.com/capitaldoengano/Moxnox-Omni.git
cd Moxnox-Omni
npm run setup
npm start
```

The installer asks for the public URL. Press Enter to use
`http://localhost:3333` while exploring locally. It then:

- creates `.env` with mode `0600`;
- generates a strong `ADMIN_API_KEY`;
- generates `WEBCHAT_SITE_TOKEN` and `META_VERIFY_TOKEN`;
- keeps provider credentials empty;
- refuses to overwrite an existing `.env`.

Copy the cockpit key printed once by the installer and open
`http://localhost:3333/cockpit`. Choose **Operação** to see the remaining
checklist and the pre-operation status. Do not send that key or the `.env` file through chat, email, issues or
pull requests.

For Docker, create `.env` with the same installer and then run:

```bash
docker compose up -d --build
```

## Public URL

Meta cannot deliver webhooks to localhost. Before connecting Instagram or
WhatsApp, publish the service behind HTTPS and change `PUBLIC_BASE_URL` to the
origin only, for example `https://omni.example.com`. Restart the service after
editing `.env`.

The cockpit will calculate:

- cockpit: `${PUBLIC_BASE_URL}/cockpit`;
- Meta callback: `${PUBLIC_BASE_URL}/webhooks/meta`.

## Where each credential comes from

### Created by Moxnox

- `ADMIN_API_KEY`: generated by `npm run setup`; opens the internal cockpit.
- `WEBCHAT_SITE_TOKEN`: generated by the installer; authenticates webchat
  ingestion.
- `META_VERIFY_TOKEN`: generated by the installer; paste the exact same value in
  the Meta webhook **Verify token** field.

### Created by Meta

1. Open [Meta for Developers](https://developers.facebook.com/apps/) and create
   or select the business app that will own the integrations.
2. In **App settings > Basic**, copy `META_APP_ID` and reveal/copy
   `META_APP_SECRET`. See the official [Basic settings
   guide](https://developers.facebook.com/documentation/development/create-an-app/app-dashboard/basic-settings).
3. Add Instagram API with Instagram Login. Connect each professional account and
   collect its Instagram account ID and access token separately. The scopes used
   by this project are `instagram_business_basic`,
   `instagram_business_manage_messages` and
   `instagram_business_manage_comments`. See the official [Instagram API
   guide](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login).
4. Save the Capital values as `CAPITAL_INSTAGRAM_ACCOUNT_ID` and
   `CAPITAL_INSTAGRAM_ACCESS_TOKEN`; save the Gu values as
   `GU_INSTAGRAM_ACCOUNT_ID` and `GU_INSTAGRAM_ACCESS_TOKEN`.
5. Add WhatsApp to the app. The API setup screen supplies the WABA ID, phone
   number ID and a test access token. Save them as
   `WHATSAPP_BUSINESS_ACCOUNT_ID`, `WHATSAPP_PHONE_NUMBER_ID` and
   `WHATSAPP_ACCESS_TOKEN`. Follow the official [WhatsApp Cloud API
   guide](https://developers.facebook.com/documentation/business-messaging/whatsapp/get-started).
6. Replace temporary tokens with production tokens managed by the correct Meta
   business and request any Advanced Access required for non-test accounts.

## Webhook setup

In the Meta app webhook settings:

1. copy the callback URL shown by the cockpit;
2. copy `META_VERIFY_TOKEN` from the local `.env` into **Verify token**;
3. verify and save;
4. subscribe to Instagram comment/message fields and WhatsApp messages required
   by the connected products;
5. keep `DELIVERY_MODE=dry-run` while sending test events;
6. inspect the inbox, review queue and planned replies in the cockpit;
7. confirm the real inbound event in the **Operação** view;
8. set `LIVE_ACCOUNTS=capital-do-engano` to release only the first pilot account;
9. use `DELIVERY_MODE=live` only after the cockpit shows no blocker.

Official references: [Instagram
webhooks](https://developers.facebook.com/documentation/instagram-platform/webhooks)
and [WhatsApp webhook endpoint](https://developers.facebook.com/documentation/business-messaging/whatsapp/webhooks/create-webhook-endpoint/).

## Applying changes

Configuration in `.env` is loaded at process start. After an edit:

```bash
# Node
npm start

# Docker
docker compose up -d --build
```

Automation copy and backlog classifications are different: those are edited in
the cockpit and become available immediately without restarting.

To stop real sending without disconnecting webhooks, restore
`DELIVERY_MODE=dry-run` and restart. Inbound events continue to be authenticated,
stored and classified while provider delivery remains disabled.

See the [pilot runbook](PILOT_RUNBOOK.md) for the opening and rollback sequence.
